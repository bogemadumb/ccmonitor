# CCMonitor

Лимиты Claude Code и Codex прямо в строке меню macOS: несколько подписок, уведомления, светлая и тёмная панель.

Мне надоело гадать, сколько осталось от лимита. Официально это нормально нигде не видно — либо упираешься в стенку без предупреждения, либо лезешь куда-то проверять вручную. Поэтому я повесил цифры прямо в menu bar: сколько сожрал от 5-часового окна, сколько времени до сброса и сколько токенов ушло. Клик по значку — раскрывается панель с деталями: оба лимита, 5 часов и 7 дней, кольцом и барами, остальные подписки списком, лимиты Codex рядом, разбивка токенов и прикидка стоимости для справки.

Штука показывает лимиты **того, у кого она установлена**. Если поставите себе — увидите свои: она берёт OAuth-токен Claude Code из вашей связки ключей (Keychain) и логи ваших сессий из `~/.claude/projects`. Наружу ничего не уходит, кроме запросов к API Anthropic за вашими же лимитами (и обновления токена у подписок, которые вы добавили в приложении). Лимиты Codex спрашивает у OpenAI сам бинарник Codex — приложение его токены не читает.

## Скриншот

В самой строке меню это компактный значок вроде `◑ 47% · 2:14` — циферблат, процент 5-часового лимита и время до сброса. Кликаешь — вылезает панель с барами лимитов 5 ч / 7 дней и разбивкой токенов за сессию.

Панель приложение снимает само (в кадре — ваши собственные лимиты, так что кладите картинку в репозиторий на своё усмотрение):

```bash
mkdir -p docs
~/Applications/CCMonitor.app/Contents/MacOS/CCMonitor --snapshot docs/screenshot.png
```

## Возможности

- **Строка меню:** значок-«циферблат» (○ ◔ ◑ ◕ ●), процент лимита и время до сброса (`◑ 47% · 2:14`). Что именно показывать, настраивается: активный Claude, Codex, оба сразу или самый загруженный лимит; окно 5 ч / неделя / оба; «израсходовано» или «осталось». От 70 % значок оранжевеет, от 90 % краснеет.
- **Панель по клику:** своя панель без стрелки (не NSPopover), светлая и тёмная тема, шрифт Inter, если он установлен. Сверху — активная подписка: кольцо 5-часового окна, время сброса и полоса недели. Ниже — **другие подписки** с двумя мини-полосами и статусом («лимит до 04.10 01:59», «нужен вход»).
- **Несколько подписок Claude:** можно добавить ещё аккаунты прямо из приложения (вход через браузер, PKCE, код вставляется в окно). Токены лежат в вашей Keychain отдельными записями `CCMonitor-account-N` и обновляются независимой цепочкой, не мешая Claude Code. Когда вы переключаетесь в Claude Code на другой аккаунт, предыдущий не теряется — приложение запоминает его.
- **Codex:** лимиты 5 ч / неделя, план, кредиты и доступные сбросы. Источник — `codex app-server` из расширения VS Code, запасной путь — журналы `~/.codex/sessions`. Опрашивает отдельный LaunchAgent раз в 5 минут; если Codex не установлен, строка просто пустая.
- **Окно настроек (4 вкладки):** аккаунты (порядок перетаскиванием, скрыть, удалить, перевойти), что показывать в строке меню, уведомления, общее (частота опроса 5/10/15 мин, пороги цвета, блоки токенов и стоимости, запуск при входе). Настройки — один файл `~/.claude/usage-monitor/settings.json`.
- **Уведомления:** на 80 % и 95 % (пороги редактируются), «лимит закончился», «окно сбросилось», «аккаунт потерял доступ». Каждый порог — один раз за окно; первый запуск только запоминает уже пройденные пороги, без залпа. Фильтр по аккаунтам и окнам.
- **Токены за сессию:** сумма по всем чатам внутри текущего 5-часового окна: ввод / вывод / запись кэша / чтение кэша, плюс справочная цена в долларах.
- **Считает по-честному:** дедуп записей по `(message.id, requestId)`, схлопывание sidechain-повторов, отдельный учёт `iterations`. Границы окна берутся из `resets_at` ответа о лимитах, поэтому токены совпадают с баром.
- **Не падает от сбоев:** ответ кэшируется, при 429 или обрыве сети показывается последнее известное значение с пометкой `*`, отсчёт до сброса считается от абсолютного времени. Подписка без доступа дольше 3 дней сама прячется из панели.
- **Автозапуск** при входе в систему через LaunchAgent.

## Как это работает

```
main.swift (AppKit: статусбар, панель, настройки)  ──запускает──>  collector.py  ──> JSON в stdout
                                                                         │
                          ┌──────────────────────────────┬───────────────┴──────────────┐
                          │                              │                              │
              Keychain: OAuth-токены          ~/.claude/projects/*.jsonl      ~/.claude/usage-monitor/
              Claude Code + CCMonitor-        (логи сессий)                   codex-usage.json
              account-N                              │                              ▲
                          │                          v                              │
                          v                   подсчёт токенов        codex-usage-local.py (LaunchAgent, 5 мин)
         api.anthropic.com/api/oauth/usage                            codex app-server / ~/.codex/sessions
         (лимиты 5 ч / 7 дней)
```

Всю логику данных я специально держу в Python — так её проще читать и править. Swift только дёргает скрипт раз в 30 секунд и рисует результат; сам опрос серверов идёт по настройке (по умолчанию раз в 5 минут).

> **Важно:** endpoint `oauth/usage` — внутренний и недокументированный. Anthropic может изменить или убрать его в любой момент, и тогда лимиты перестанут показываться (токены из логов продолжат считаться). Ценник моделей в `PRICING` (`collector.py`) — справочный и зашит вручную: при подписке вы этих денег не платите, а при изменении цен таблицу нужно поправить руками.

## Стек

- **Swift + AppKit** — приложение в строке меню (`LSUIElement`, без иконки в доке), universal binary (arm64 + x86_64).
- **Python 3** — сбор данных, только стандартная библиотека, никаких зависимостей.
- **launchd** — автозапуск.

## Требования

1. **macOS 13 (Ventura) или новее**, Apple Silicon или Intel.
2. **Claude Code**, установленный и залогиненный, с подпиской Pro или Max. Без него данных не будет: приложение читает токен и логи именно оттуда.
3. **Xcode Command Line Tools** — нужны `swiftc` (сборка) и `python3`:
   ```bash
   xcode-select --install
   ```

Никаких API-ключей, токенов ботов и файлов `.env` заводить не нужно — приложение использует ваш собственный вход в Claude Code.

## Установка

```bash
git clone https://github.com/<ваш-аккаунт>/ccmonitor.git
cd ccmonitor
```

### 1. Сборка и установка приложения

```bash
bash build.sh
```

Скрипт компилирует Swift (universal, если доступен x86_64-таргет), собирает бандл `CCMonitor.app` с вложенными `collector.py` и `codex-usage-local.py` и ставит его в `~/Applications/`. Если настроена подпись (`bash signing-setup.sh`, один раз), бандл подписывается самоподписанным сертификатом: разрешения macOS тогда переживают пересборку. Без неё — ad-hoc подпись.

### 2. Автозапуск при входе в систему

`install.sh` ставит два LaunchAgent (`com.ccmonitor.app` — само приложение, `com.ccmonitor.app.codex` — сбор лимитов Codex), но ожидает собранное приложение рядом с собой, поэтому кладём его в папку репозитория на время установки:

```bash
cp -R ~/Applications/CCMonitor.app .
bash install.sh
rm -rf CCMonitor.app          # копия больше не нужна
```

Иконка появится в строке меню справа вверху. При первом обращении к паролю Claude Code macOS спросит доступ к связке ключей — нажмите **«Всегда разрешать»**, иначе диалог будет всплывать каждые 30 секунд.

> `CCMonitor.app` уже прописан в `.gitignore` — временная копия не попадёт в коммит.

### 3. Проверка

```bash
python3 collector.py --pretty
```

Должен вывести JSON с ключами `limits` и `tokens`. Если да — данные идут, и статусбар их покажет.

### Обновление

```bash
git pull && bash build.sh
launchctl kickstart -k "gui/$(id -u)/com.ccmonitor.app"
```

### Удаление

```bash
launchctl bootout "gui/$(id -u)/com.ccmonitor.app"
launchctl bootout "gui/$(id -u)/com.ccmonitor.app.codex"
rm -rf ~/Applications/CCMonitor.app ~/Library/LaunchAgents/com.ccmonitor.app*.plist
rm -rf ~/.claude/usage-monitor
```

## Структура

```
├── main.swift             Приложение в строке меню: опрос collector'а раз в 30 с, панель,
│                          окно настроек, уведомления (AppKit). Служебные режимы:
│                          --snapshot <path>, --snapshot-settings <path>, --test-engine, --test-notify.
├── collector.py           Вся логика данных. Печатает JSON в stdout: лимиты всех подписок
│                          (с кэшем и бэкоффом), токены из JSONL с дедупом, срез Codex.
│                          Также вход в подписку: --login-url / --login-code (код из stdin) / --delete.
├── codex-usage-local.py   Снимает лимиты Codex (app-server, запасной путь — журналы сессий).
├── test_collector.py      Тесты collector'а и codex-usage-local.py. Запуск: python3 test_collector.py
├── build.sh               Компиляция Swift + сборка .app + подпись + установка в ~/Applications.
├── signing-setup.sh       Самоподписанный сертификат в отдельной связке ключей (один раз).
├── install.sh             Установка .app + два LaunchAgent (приложение и Codex).
├── Info.plist             Манифест бандла (LSUIElement — приложение без иконки в доке).
└── AppIcon.icns           Иконка приложения.
```

Рантайм-данные вне репозитория: `~/.claude/usage-monitor/` (кэши лимитов, `settings.json`, состояние уведомлений).

## Тесты

```bash
python3 test_collector.py
```

Проверяются кэш и бэкофф, 429, отсутствие сети, битый JSON, пустые логи, дедуп токенов, границы окна, несколько аккаунтов, вход и удаление подписки (Keychain подменяется), настройки и скрытие, срез Codex (app-server и журналы), e2e-прогон подпроцессом. Ожидаемо: `Итог: 72/72 прошло`. Движок уведомлений проверяется самим приложением: `CCMonitor --test-engine`.

## Траблшутинг

| Что видно | Причина и что делать |
|---|---|
| В строке меню `CC …` | Collector не отдаёт данные. Запустите `python3 collector.py --pretty` и посмотрите поле `error`. |
| `CC ⚠︎` / «Токен истёк» | OAuth-токен протух. Откройте Claude Code и залогиньтесь — токен обновляется, когда Claude Code запущен. |
| «Лимиты обновляются…» | HTTP 429: endpoint строго rate-limited. Само пройдёт, опрос идёт не чаще раза в 2 минуты. |
| Звёздочка в `47%* · 2:14` | Показано последнее известное значение (сеть или 429), время до сброса при этом верное. |
| `error: no_token` | Claude Code не установлен, не залогинен, или вы запретили доступ к Keychain. Проверка: `security find-generic-password -s "Claude Code-credentials"`. |
| Постоянный запрос пароля | При диалоге Keychain нажмите «Всегда разрешать», а не «Разрешить». |
| «Не удаётся открыть: неустановленный разработчик» | Приложение не подписано. `xattr -dr com.apple.quarantine ~/Applications/CCMonitor.app`, затем Системные настройки → Конфиденциальность и безопасность → «Открыть всё равно». |
| `swiftc: command not found` | `xcode-select --install`. |
| Иконки нет вообще | `launchctl list \| grep ccmonitor` — если пусто, повторите шаг 2. Логи: `log show --predicate 'process == "CCMonitor"' --last 5m`. |
| Токены есть, лимиты — нет | Вероятно, Anthropic изменила внутренний endpoint `oauth/usage`. |
| Пусто после обновления macOS | Пересоберите: `bash build.sh`. |
| Codex пустой или «нет данных» | Codex не установлен, либо app-server не ответил за 25 с. Запустите `python3 codex-usage-local.py` и посмотрите `~/.claude/usage-monitor/codex-usage.json`. |
| Подписка помечена «нужен вход» | Refresh-токен отозван или истёк: «Перевойти» в настройках, вкладка «Аккаунты». |
| Нет уведомлений | Приложение шлёт их через `osascript`, а не UNUserNotificationCenter (тот не даёт разрешения неподписанному бандлу). Лог: `~/.claude/usage-monitor/notify.log`. |
